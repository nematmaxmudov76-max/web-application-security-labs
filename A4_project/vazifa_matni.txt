1.3. Autentifikatsiya: to‘g‘ri va noto‘g‘ri kirish
Firefox bosh sahifasida ali va noto‘g‘ri parol bilan kiring. Networkda /login javobi 401, matni “Login yoki parol xato.” bo‘lsin. Bosh sahifani manzil orqali qayta oching, mavjud bo‘lmagan login bilan takrorlang. Javob matni aynan bir xil bo‘lishi kerak. Bu xabar foydalanuvchi mavjudligini oshkor qilmaslikka yordam beradi; barcha vaqt farqlarini yo‘qotishni kafolatlamaydi. [1]
Endi ali / Ali-A4-Only! bilan kiring. /login 200 qaytaradi. Brauzer JSON natijani ko‘rsatadi; manzil satrida bosh sahifani qayta oching, so‘ng “Mening rolim” havolasiga o‘ting. /api/me javobida id=1 va role=student chiqadi.
curl uchun alohida sessiya yaratish
Quyidagi blok anonim sessiya va unga tegishli CSRF token oladi, so‘ng login so‘rovini yuboradi. Parol sun’iy o‘quv qiymatidir. -b cookie o‘qiydi, -c esa javobdan yangilangan cookie yozadi.
curl --noproxy "*" -s -c ali.cookies "$A4_BASE/api/csrf" > csrf.jsonA4_CSRF=$(python3 -c 'import json; print(json.load(open("csrf.json"))["csrf"])')cp ali.cookies anon.cookiescurl --noproxy "*" -i -b ali.cookies -c ali.cookies \  -H "X-CSRF-Token: $A4_CSRF" \  --data-urlencode 'username=ali' \  --data-urlencode 'password=Ali-A4-Only!' "$A4_BASE/login"
Muvaffaqiyatli login javobidagi Set-Cookie sarlavhasini va ikki fayldagi SIDni solishtiring:
cat anon.cookiescat ali.cookiescurl --noproxy "*" -i -b ali.cookies "$A4_BASE/api/me"curl --noproxy "*" -i -b anon.cookies "$A4_BASE/api/me"
anon.cookies va ali.cookies ichidagi a4_sid qiymatlari farqlanishi kerak. Yangi cookie bilan /api/me → 200; anonim eski cookie bilan → 401. Kodingizdagi SESSIONS.pop(sid, None) va issue_session(name) qatorlari eski sessiyani bekor qilib, yangi SID yaratadi.
CSRF token va SIDni adashtirmang
SID foydalanuvchi sessiyasini topishga xizmat qiladi va HttpOnly cookie bilan yuboriladi. CSRF token forma yoki X-CSRF-Token sarlavhasida yuboriladi; u shu sessiyaga tegishliligini tekshiradi. Login SID va CSRF tokenni yangilaydi, shuning uchun logout uchun tokenni keyin qayta olish kerak. [4, 6]
Login so‘rovini CSRFsiz yuborsangiz, parol to‘g‘ri bo‘lsa ham 403 chiqadi. Bu autentifikatsiya muvaffaqiyatsizligi bilan bir xil sabab emas. D1 daliliga noto‘g‘ri/to‘g‘ri login, SID o‘zgarishi va cookie atributlarini kiriting.
Sessiya qiymatlarini hisobotda to‘liq ochmang: birinchi va oxirgi bir necha belgini qoldirib, o‘rtasini yoping. HttpOnly cookie curl faylida #HttpOnly_ bilan boshlangan satrda ko‘rinishi mumkin; buni keraksiz izoh deb o‘chirib yubormang.

1.5. Boshqariladigan zaiflik: boshqa talabaning hujjati
Server terminalida Ctrl+C bosing va zaif rejimni ishga tushiring. Qayta ishga tushirish barcha sessiyalarni yo‘qotadi. 1.3dagi curl login blokini takrorlab, Ali uchun yangi cookie oling:
python app.py --weak-authz
Ali sifatida /api/docs/102ni so‘rang: endi 200 va Valining o‘quv hujjati chiqadi. /api/admin hanuz 403. Demak, autentifikatsiya va rol nazorati borligi obyekt egasini tekshirish o‘rnini bosmaydi. D3ga zaif rejimdagi 102-hujjat natijasini saqlang.
Bu misol obyekt darajasidagi kirish nazorati buzilishi, ya’ni IDOR/BOLA mazmunini ko‘rsatadi. Raqamli IDning o‘zi zaiflik emas; asosiy sabab so‘ralgan obyekt uchun ruxsat tekshiruvi chetlab o‘tilganidir. Faqat IDni uzun yoki tasodifiy qilish bu nazoratni almashtirmaydi. [2]

1.3dagi login blokini qayta bajaring. Ali uchun 101 → 200, 102 → 403, admin → 403; Vali uchun o‘z 102-hujjati → 200; administrator uchun ikkala hujjat → 200 bo‘lsin. --weak-authz turganiga qaramay boshqa egaga oid hujjat rad etilishi koddagi chetlab o‘tish olib tashlanganini ko‘rsatadi.
Faqat --weak-authzni o‘chirib qayta ishga tushirish zaif tarmoqni koddan olib tashlamaydi. Ushbu topshiriqda haqiqiy tuzatish satrini va uning qayta sinovini ko‘rsatish talab etiladi. D4ga avvalgi/tuzatilgan shart va ruxsat matritsasining qayta tekshirilgan qismini qo‘shing.
1.7. Cookie himoya atributlarini kuzatish
Firefoxda bosh sahifani ochib kiring. Network → /login → Response Headers ichidagi Set-Cookieni ko‘ring; Storage → Cookiesda atributlarni tekshiring. Cookie nomi a4_sid, Path=/, HttpOnly va SameSite=Lax bo‘lishi kerak.
Console oynasida document.cookie qiymatini ko‘ring: a4_sid ko‘rinmasligi kerak. Biroq shu sahifadan serverga yuborilgan odatiy so‘rovga brauzer cookie qo‘shadi. HttpOnly autentifikatsiyani yoki avtorizatsiyani almashtirmaydi, faol XSSning barcha ta’sirini ham bartaraf etmaydi. [5]
Cookie port bo‘yicha ajratilmaydi. Ushbu ish a4_sid nomidan foydalanadi; A1–A3 cookie nomlari bilan aralashtirmang. localhost va 127.0.0.1 hostlari esa alohida. Sinovlar davomida faqat ko‘rsatilgan hostni ishlating.
secure=False holatini hisobotda lokal HTTP uchun berilgan istisno sifatida yozing. TLSni sozlamasdan bu atributni o‘zgartirish brauzer xatti-harakatiga ta’sir qilishi mumkin; ushbu darsda asosiy dalil cookie sarlavhasi va server tekshiruvidir.
1.8. Chiqishdan keyin eski sessiyani qayta ishlatib ko‘rish
Tuzatilgan server ishlayotganida Ali uchun faol curl sessiya yaratilgan bo‘lsin. Avval uning cookie faylidan nusxa oling. Bu o‘z o‘quv sessiyangizning nazorat nusxasi:
cp ali.cookies replay.cookiescurl --noproxy "*" -i -b replay.cookies "$A4_BASE/api/me"curl --noproxy "*" -i -b ali.cookies -X POST "$A4_BASE/api/logout"
Birinchi so‘rov 200, CSRFsiz logout 403 bo‘ladi. Endi joriy sessiyaning yangi CSRF tokenini oling va to‘g‘ri logout yuboring:
curl --noproxy "*" -s -b ali.cookies -c ali.cookies "$A4_BASE/api/csrf" > csrf.jsonA4_CSRF=$(python3 -c 'import json; print(json.load(open("csrf.json"))["csrf"])')curl --noproxy "*" -i -b ali.cookies -c ali.cookies -X POST \  -H "X-CSRF-Token: $A4_CSRF" "$A4_BASE/api/logout"curl --noproxy "*" -i -b replay.cookies "$A4_BASE/api/me"
To‘g‘ri logout → 200; o‘chirilmagan eski replay.cookies bilan /api/me → 401. Serverdagi SESSIONS.pop sessiyani bekor qilgani uchun brauzerda cookie nusxasi saqlanib qolsa ham u qayta ishlamaydi. Faqat mijoz cookie faylini o‘chirish bunday isbotni bermaydi. [4]
1.9. Sessiya muddatini qisqa tajribada tekshirish
Oddiy rejimda sessiyaning mutlaq muddati 1200 soniya — 20 daqiqa. So‘rovlar bu muddatni uzaytirmaydi. Qisqa sinov uchun serverni to‘xtatib, tuzatilgan kodni quyidagicha ishga tushiring:
python app.py --ttl 20
1.3dagi curl login blokini tezda bajaring. Muvaffaqiyatli login olingandan so‘ng 20 soniyadan oldin /api/me so‘rovi 200 qaytarsin. Keyin ikkinchi terminalda:
sleep 22curl --noproxy "*" -i -b ali.cookies "$A4_BASE/api/me"
Kutiladigan natija: 401. Shu tekshiruv orasida /api/csrfga kirmang va qayta login qilmang. Cookie faylda mavjud bo‘lishi mumkin; yaroqlilikni server tekshiradi. D5ga chiqishdan keyingi va muddat tugagandan keyingi natijalarni yozing.
Sessiyaning hayot siklini xulosa qilish
Anonim kirish: vaqtinchalik SID va CSRF yaratiladi; himoyalangan endpointlar hali 401 qaytaradi.
To‘g‘ri login: eski SID o‘chiriladi, yangi autentifikatsiyalangan sessiya yaratiladi.
Har so‘rov: SID mavjudligi va tugash vaqti tekshiriladi, keyin rol va obyekt huquqi baholanadi.
Logout yoki muddat tugashi: server yozuvi bekor qilinadi. Server qayta ishga tushsa barcha in-memory sessiyalar yo‘qoladi.
Tajriba tugagach serverni oddiy python app.py bilan qayta ishga tushiring; tuzatilgan app.py nusxasini saqlang.
