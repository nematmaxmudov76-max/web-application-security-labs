A8. API xavfsizligi va zamonaviy autentifikatsiya mexanizmlari
1-VARIANT — O‘quv buyurtmalar API xizmatini himoyalash
Mashg‘ulot maqsadi. JWT orqali kelgan foydalanuvchi identifikatorini tekshirish, buyurtma egasi va administrator
huquqlarini alohida nazorat qilish hamda autentifikatsiyadan o‘tgan mijoz uchun so‘rovlar tezligini cheklash. Har
bir himoya natijasi HTTP javobi va qonuniy nazorat so‘rovi bilan asoslanadi.
Kutiladigan natija. Talaba imzo va claim tekshiruvini oddiy dekodlashdan, autentifikatsiyani obyekt hamda
funksiya darajasidagi avtorizatsiyadan ajratadi. Uchta zaif funksiyani tuzatadi va aynan avvalgi endpointlarda qayta
sinaydi. API kaliti, GraphQL va API Gateway vazifalarini misol bilan izohlaydi.

1.5. Rate Limiting va uchta tuzatish
5-topshiriq. Har bir rejimga olti so‘rov yuboring. Bu yuklama sinovi emas: bitta mijozning olti ketma-ket murojaati
kifoya. Sikl 10 soniyadan tez yakunlansin; safe katalogiga oldindan so‘rov yubormang yoki avvalgi oynaning
tugashini kuting.
for mode in weak safe; do
echo "Rejim: $mode"
for i in 1 2 3 4 5 6; do
curl -s -o /dev/null -w "%{http_code}\n" \
-H "Authorization: Bearer $ALI" "$BASE/api/$mode/catalog"
done
done
curl -i -H "Authorization: Bearer $ALI" "$BASE/api/safe/catalog"

Weak: oltita 200. Safe: beshta 200, keyin 429. Oyna hali tugamagan bo‘lsa oxirgi curl -i ham 429 va Retry-After
beradi. Sarlavhadagi soncha soniya kutib, ayni so‘rovni takrorlang: 200 qaytishi kerak. Bu kutishdan oldin VALI
tokeni bilan safe katalogni bir marta chaqiring: uning alohida kvotasi sabab 200 bo‘ladi.
limit_safe() monotonic vaqt, sirpanma oyna va Lock bilan ishlaydi. Hisob sub bo‘yicha yuritiladi; yangi token olish
o‘sha sub kvotasini yangilamaydi. Limit faqat katalog endpointlariga qo‘llanadi. Xotiradagi holat server qayta
boshlanganda yo‘qoladi; ko‘p worker yoki server uchun umumiy hisoblagich kerak. [6]
6-topshiriq. Avvalgi /weak endpointlarini tuzatish
1-terminalda Ctrl+C bosing. app_before.py boshlang‘ich nusxa bo‘lib qolsin. app.py ichidagi quyidagi uchta
funksiya tanasini almashtiring:
def order_weak(user, order):
return order_safe(user, order)
def admin_weak(user):
return admin_safe(user)
def limit_weak(sub):
return limit_safe(sub)

Bu tuzatish himoya funksiyalarini aynan avvalgi marshrutga ulaydi. order_safe va admin_safe ichidagi shartlarni
ham tushuntiring; faqat manzilni /safega o‘zgartirish topshiriq bajarilgani hisoblanmaydi.
python -m py_compile app.py
python app.py

Dalil D5. /weak/orders/202 + ALI endi 403; /weak/admin/summary + ALI ham 403. ALI o‘z buyurtmasiga va ADMIN
summaryga 200 olsin. Server qayta boshlanganidan keyin faqat /weak/catalogga oltita so‘rov yuboring: 200 × 5, 429.
Tuzatishdan so‘ng /safe va /weak bir sub hisoblagichini bo‘lishadi.

def limit_safe(sub):
